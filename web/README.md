# Tank Arena Web

React + TypeScript 前端，包含玩家驾驶页和观战计分页。默认进入本地模拟模式，无需服务器或坦克。

## 开始运行

安装 **Node.js 22.12+（推荐 Node.js 24 LTS）**，在仓库的 `web` 目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。构建和测试：

```sh
npm test
npm run build
npm run preview
```

不想启动开发环境时，可以执行 `npm run demo:export`，生成一个独立的 `dist/tank-arena.html`。将这个文件发给队友，直接用浏览器打开即可体验本地模拟模式，不需要联网或安装依赖。实际连接树莓派时建议仍使用 HTTP 托管的正式页面。

从局域网其他设备访问开发预览：`npm run dev -- --host 0.0.0.0`。正式部署应使用 `dist/` 静态文件，不使用 Vite 开发服务器。

## 模拟演练

1. 默认两台模拟坦克在线，玩家已就绪。
2. 玩家页：WASD / 方向键驾驶；在瞄准区左右移动鼠标转动炮塔；空格、开火按钮或点击瞄准区射击。也可使用方向按钮和角度滑块。
3. 练习阶段命中会显示记录，不扣血、不耗弹，仍有 1 秒开火间隔。
4. 切到「观战计分」，点击「开始比赛」。3 秒倒计时后进入比赛，再返回驾驶。
5. 5 点血量、10 发弹药、每 3 秒补 1 发、死亡 5 秒复活、复活后 2 秒保护。先到 5 杀或 3 分钟结束。
6. 默认自动对手每 2.4 秒尝试射击，可取消「自动对手」。比赛结束后在观战页重置。

模拟器仅用于前端演示：允许的射击直接模拟命中，不模拟位置、射线、红外帧、真实命中校验和网络延迟。瞄准圆盘只是炮塔角度示意，没有摄像头或位置反馈。

每个浏览器标签页的模拟比赛独立，刷新即重置；同一页面切换驾驶／观战会保留模拟比赛。

## 对接真实服务器

点击右上角「连接设置」，选择「真实服务器」，输入 `ws://10.42.0.1:8000`、玩家名及坦克编号。页面自动选择：

| 身份 | 路径            | 第一条消息                                        |
| ---- | --------------- | ------------------------------------------------- |
| 玩家 | `/ws/player`    | `{"type":"hello","tank_id":1,"name":"Player 01"}` |
| 观众 | `/ws/spectator` | `{"type":"hello"}`                                |

真实比赛需要 **两个玩家页面 + 一个独立计分页**。玩家在同一标签页切换成观众会释放原玩家连接。真实模式右上角的外链按钮可打开新的计分页；新页面默认仍是模拟模式，请在设置中选择真实服务器，避免刷新时自动接管实物。

- `drive` 固定 20 Hz，整数履带速度 -100..100、炮塔角度 -90..90。
- 点击开火发送 `{"type":"fire"}`；前端不分配 `shot`、不发送 `hit`、不计算真实 HP 或比分。
- 回复服务器 JSON `ping` 为带相同 `ts` 的 `pong`。
- 接受 `state`、`event`、`error`；在收到第一条有效完整 `state` 后才启用控制。
- 3 秒收不到消息即关闭连接；断线每 1 秒重连并重新发送 `hello`。注册被拒绝且服务器断开时停止重试，修改设置后重连。
- 窗口失焦、页面隐藏、松键、锁定、切换身份或设置时发送停车并清除按键。不重放断线前的驾驶输入。
- 倒计时、死亡、离线、比赛结束、连接未就绪时禁用驾驶与开火。
- 比赛开始、重置仅经 spectator 连接发送。
- HTTPS 托管页面要求 `wss://`；树莓派提供普通 `ws://` 时请从 HTTP 局域网页面访问。

按用户提供的 **[协议快照](docs/PROTOCOL.md)** 实现。`dev-tank` 当前固件的 `state/enable`、`event/kind` 是另一套坦克端命名；此页面不会自行改写组内协议。服务器与固件需要统一约定后再联调。

后端实现应负责角色权限、玩家占用、参数验证、命中合法性、冷却、血量、弹药和胜负。前端禁用按钮不替代服务端校验。实物固件仍必须独立实现断线／300 ms 超时停车。

## 结构

```text
src/App.tsx             页面、设置、控制及计分展示
src/style.css           响应式界面样式（无远程字体依赖）
src/protocol.ts         消息类型、验证、连接地址与角色限制
src/connection.ts       真实 WebSocket / 本地模拟两种传输
src/mockArena.ts        可单独测试的模拟比赛状态机
src/hooks.ts            会话管理和驾驶输入生命周期
src/controls.ts         差速履带按键计算
src/*.test.*           协议、传输、模拟比赛、驾驶行为测试
docs/PROTOCOL.md        本次实现使用的协议原文
```

`state` 是完整快照；页面直接显示服务器给出的 HP、弹药、复活计时和比赛计时，不在真实模式下用模拟数据补位。协议中未包含位置、电量或延迟，因此页面不伪造这些实机数据。

## 联调验收清单

- [ ] 两个玩家分别注册坦克 1 / 2；重复占用显示后端错误，不进入无限重试。
- [ ] 观众能够看到两位玩家和在线状态，开始和重置可用。
- [ ] 坦克收到持续 20 Hz 驾驶消息；松键、切出窗口和断网后实物停车。
- [ ] 开火由服务器分配 shot，真实 IR 命中通过服务端判断后才更新网页。
- [ ] 死亡锁定、5 秒复活、补弹、倒计时、胜负与重置正确同步。
- [ ] 断线重连重新注册，未恢复旧移动输入。

自动测试覆盖协议验证、角色限制、心跳、重连、拥塞处理、20 Hz 发送、失焦／松键／锁定停车以及模拟游戏规则。实物验收仍需要服务器和两台坦克完成。
